# Crochet by Nouhad

The online shop for Nouhad's handmade crochet, in **French** (the default) and
**Arabic** (right to left). Guest checkout with cash on delivery anywhere in
Morocco; every order is then confirmed with Nouhad on WhatsApp. Nouhad manages
pieces, photos, categories and orders in `/admin` (French only).

- Shop: `/fr/...` and `/ar/...`. `/` sends a visitor to the language they
  picked last, else to the one their browser asks for, else to French.
- Design: the « Le fil » system, see [`docs/design/`](docs/design).

## Stack

Next.js 16 (App Router, Turbopack, `proxy.ts`) · React 19 · TypeScript ·
Tailwind CSS 4 · shadcn/ui on Base UI · Drizzle ORM · Neon Postgres ·
Auth.js 5 (credentials) · Zod 4

## Run it

Needs Node 20 or newer and a Postgres database (Neon works on its free plan).

```bash
npm install
cp .env.example .env.local      # then fill it in, see below
npx drizzle-kit migrate         # creates the tables
npm run seed                    # optional: 6 sample pieces (run once only)
npm run seed:ar                 # optional: Arabic text for those samples and the categories
npm run create-admin -- you@example.com 'a-long-password'
npm run dev                     # http://localhost:3000
```

Other commands:

```bash
npm run lint
npx tsc --noEmit                # after one `npm run build`: route types are generated by the build
npm run build && npm run start  # production build, see the WhatsApp note below
```

`/fr/styleguide` shows every component in every state. It exists in
development only (a 404 in production).

### Running a production build locally

A production build refuses to run without a real Moroccan WhatsApp number and
the public URL. To try one on your machine, give them for that command only:

```bash
NEXT_PUBLIC_SITE_URL=http://localhost:3100 NEXT_PUBLIC_WHATSAPP_NUMBER=2126XXXXXXXX npm run build
NEXT_PUBLIC_SITE_URL=http://localhost:3100 NEXT_PUBLIC_WHATSAPP_NUMBER=2126XXXXXXXX npx next start -p 3100
```

## Environment variables

Secrets live in `.env.local` (git-ignored) locally and in the host's settings
in production. [`.env.example`](.env.example) lists every variable with an
empty value. Never commit a real value.

| Variable | Needed | What it does |
| --- | --- | --- |
| `DATABASE_URL` | always | Postgres connection string (Neon). |
| `AUTH_SECRET` | always | Signs the admin's session cookie. Generate one with `npx auth secret`. |
| `NEXT_PUBLIC_WHATSAPP_NUMBER` | always | Nouhad's WhatsApp, digits only with the country code, no `+` (`2126…`). Every "order on WhatsApp" link uses it. A production build stops if it is missing, not Moroccan, or the placeholder `212600000000`. |
| `NEXT_PUBLIC_SITE_URL` | production | The public address, no trailing slash (`https://example.com`). Used for canonical links, `hreflang`, the sitemap and link previews. On Vercel it falls back to the project's production URL (`VERCEL_PROJECT_PRODUCTION_URL`, then `VERCEL_URL`, both set by Vercel); elsewhere the build fails without it. |
| `AUTH_TRUST_HOST` | off Vercel | Set to `true` when hosting anywhere other than Vercel or Cloudflare, or every admin login fails with `UntrustedHost`. |
| `RESEND_API_KEY` | optional | With `ADMIN_NOTIFY_EMAIL`, emails Nouhad each new order through [Resend](https://resend.com). Without both, nothing is sent and orders still work. |
| `ADMIN_NOTIFY_EMAIL` | optional | Where that email goes. |
| `RESEND_FROM` | optional | A sender verified in Resend. Without it, Resend's test sender is used, which only delivers to the Resend account's owner. |

`NODE_ENV`, `VERCEL_URL` and `VERCEL_PROJECT_PRODUCTION_URL` are set by the
tooling or the host, not by you.

## Editing content in both languages

### Pieces and categories (in `/admin`)

- **A piece** has a French name and description (required) and an Arabic name
  and description (optional). While the Arabic is empty, the Arabic shop shows
  the French text, marked `lang="fr"` so screen readers read it in French.
- **A category** gets its Arabic name in *Catégories*. Empty means the Arabic
  shop shows the French name.
- **Price, reference, sold or available** are the same in both languages.
- Prices are stored in **centimes** (`25000` is 250,00 MAD) and always shown
  through `formatPrice`. Both languages use Western digits (`250,00 MAD`).

### Photos

- **Only photos of Nouhad's own work.** Never a stock picture, never an image
  taken from another website. Where there is no photo yet, the site shows a
  plain beige block with the piece's name.
- In `/admin`, open a piece and paste the photo's **https link** (photos are
  linked, not uploaded: Vercel Blob, or any host you control). The first photo
  is the main one; the arrows reorder them.
- Links on `*.public.blob.vercel-storage.com` are resized and converted by
  Next.js. Any other host is shown as is, so keep those files small (about
  1600 px wide, JPEG or WebP).
- The photo's description for screen readers is the piece's name, in each
  language. Gallery thumbnails are buttons named "Voir la photo 1",
  "Voir la photo 2"… (and the same in Arabic).
- The newest piece still for sale becomes the home page's first photo.

### The workshop photo

The home page's *L'atelier* band takes one photo of Nouhad at work. Until
there is one, the band is text only. To add it, edit
[`src/lib/content/site.ts`](src/lib/content/site.ts):

```ts
export const ATELIER_PHOTO = {
  url: "https://….public.blob.vercel-storage.com/atelier.jpg",
  alt: {
    fr: "Les mains de Nouhad crochetant un sac en raphia",
    ar: "يدا نهاد تحيكان حقيبة من الرافيا",
  },
};
```

### Interface text, legal pages, WhatsApp messages

Every word of the interface is in
[`src/i18n/dictionaries/fr.ts`](src/i18n/dictionaries/fr.ts) and
[`ar.ts`](src/i18n/dictionaries/ar.ts). That includes the legal pages
(`legal`) and the prefilled WhatsApp messages (`whatsapp`).

- `fr.ts` defines the shape; `ar.ts` must have exactly the same keys, or
  `npx tsc --noEmit` fails. That is how a missing translation is caught.
- `{name}` placeholders are filled by `fill()`; keep them in both languages.
- Strings that change with a number (`1 pièce`, `2 pièces`) are objects with
  plural forms. Arabic uses `zero`, `one`, `two`, `few`, `many` and `other`.
- In Arabic, use the Arabic comma `،`. Latin words inside Arabic text (the
  brand, `CN-0005`, prices) are wrapped in `<bdi>` in the components, so they
  never pull the punctuation out of place.
- The Arabic copy still needs a native read:
  [`docs/i18n/translations-review.md`](docs/i18n/translations-review.md)
  lists every string and the open questions.

The Instagram link is `INSTAGRAM_URL` in
[`src/lib/constants/strings.ts`](src/lib/constants/strings.ts).

## Adding a translated page

Say an "À propos" page at `/fr/a-propos` and `/ar/a-propos`:

1. **Text.** Add its strings to `fr.ts` (for example `about: { title,
   description, body }`), then the same keys to `ar.ts`.
2. **Page.** Create `src/app/[lang]/a-propos/page.tsx`. Every file under
   `[lang]` is served in both languages.

   ```tsx
   import type { Metadata } from "next";

   import { alternatesFor, openGraphFor } from "@/i18n/metadata";
   import { getDictionary, getLang } from "@/i18n/server";

   export async function generateMetadata(): Promise<Metadata> {
     const t = await getDictionary();
     const lang = await getLang();
     const { title, description } = t.about;
     return {
       title,
       description,
       // canonical + hreflang (fr, ar, x-default)
       alternates: alternatesFor(lang, "/a-propos"),
       // its own link preview, not the home page's
       openGraph: openGraphFor(lang, "/a-propos", { siteName: t.siteName, title, description }),
     };
   }

   export default async function AboutPage() {
     const t = await getDictionary();
     return (
       <article className="mx-auto max-w-prose px-4 py-section">
         <h1 className="text-4xl">{t.about.title}</h1>
         <p className="mt-6">{t.about.body}</p>
       </article>
     );
   }
   ```

   In a client component, use `const { t, href } = useI18n()` instead.
3. **Links.** Never write `/fr/…` by hand: use `localePath(lang, "/a-propos")`
   on the server or `href("/a-propos")` on the client. Add the link to the
   header (`src/components/nav-links.tsx`) or the footer
   (`src/components/site-chrome.tsx`) if it belongs there.
4. **Sitemap.** Add `...entry("/a-propos", "yearly", 0.3)` in
   [`src/app/sitemap.ts`](src/app/sitemap.ts).
5. **Layout.** Use logical classes so the page mirrors itself in Arabic:
   `ms-`/`me-`, `ps-`/`pe-`, `inset-s-`, `text-start`. Never `ml-`, `left-`
   or `text-left`. Only directional icons (arrows, chevrons) flip, with
   `rtl:-scale-x-100`.
6. **Check** both languages at 375 px and 1440 px, then run
   `npx tsc --noEmit` and `npm run lint`.

## How it works

- **Prices** are integer MAD centimes everywhere. The browser only sends
  product ids; the checkout reads the prices again on the server.
- **Every piece is one of a kind.** Checkout reserves it with one conditional
  `UPDATE … WHERE is_sold_out = false`, so two orders for the same piece cannot
  both succeed. Cancelling an order puts its pieces back on sale.
- **Pieces are never deleted**, only deactivated, because orders keep pointing
  at them.
- **The cart** lives in the browser (`localStorage`).
- **Languages:** `src/proxy.ts` handles the `/` redirect and the language
  cookie. `app/[lang]/layout.tsx` sets `<html lang dir>` from the URL. The admin
  has its own root layout in `app/admin`.

## Security

- Every admin page calls `requireAdmin()` and every admin server action
  `getAdmin()`. `src/proxy.ts` only redirects screens; it is not the check.
- Checkout: Zod validation on the server, a hidden honeypot field, at most 3
  orders per phone and 5 per IP per hour.
- Admin login: bcrypt, at most 5 failed attempts per email and 10 per IP per
  15 minutes, the same answer for an unknown email and a wrong password.
- The order confirmation link carries a random token, never the order number.
- Response headers: HSTS, `nosniff`, `X-Frame-Options: DENY`, a strict
  referrer policy. There is no Content-Security-Policy yet, see
  [`docs/audit/phase-7-audit.md`](docs/audit/phase-7-audit.md).
- The rate limits trust the `x-forwarded-for` header, which Vercel sets. On
  another host, make sure the proxy overwrites it.

## Deploying (Vercel)

1. Import the repository into Vercel.
2. Set the environment variables above (at least `DATABASE_URL`,
   `AUTH_SECRET`, `NEXT_PUBLIC_WHATSAPP_NUMBER`, `NEXT_PUBLIC_SITE_URL`).
3. Run `npx drizzle-kit migrate` against the production database once, then
   `npm run create-admin`.
4. Smoke test: add a piece to the bag, place an order, find it in `/admin`,
   then cancel it so the piece goes back on sale.
